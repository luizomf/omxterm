# First-time reader audit

This review checks whether a new user can choose a download, install OMXTerm,
open the first terminal, and follow each human-facing guide without needing
project-internal knowledge. It checks wording and links in the repository; it
does not prove that an installer, graphics backend, extension, or desktop works
on a particular computer.

| Guide                                         | Concrete first-time-user blocker or limit                                                                                                                                                   | Disposition                                                                                                                                                                                                                                                                                                           |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [README](../README.md)                        | Linux users may not know what X11 or XWayland means when checking display requirements.                                                                                                     | The guide now says X11 is a Linux window system and explains XWayland as the compatibility layer used on Wayland desktops. Platform and build-only limits remain explicit.                                                                                                                                            |
| [Installation](installation.md)               | The same Linux display terms could make a user install the wrong system packages or assume a separate app is needed.                                                                        | The guide now explains X11/XWayland. It already defines AppImage, glibc and FUSE, gives architecture checks, and includes recovery steps for the macOS warning, Linux FUSE errors and Windows runtime requirement. A clean installation still needs a real supported desktop.                                         |
| [Everyday use](usage.md)                      | Terms such as “scrollback,” “alternate screen,” “bracketed paste,” and “shell-quoted” describe behavior a new user needs to predict before searching, exporting, pasting or dropping paths. | The guide uses plain descriptions of terminal history, full-screen programs, protected pastes and quoted paths. It retains concrete menus, shortcuts and recovery instructions.                                                                                                                                       |
| [Configuration](configuration.md)             | The first-launch file tree showed `snippets.yaml` even where Snippets is optional and the file is absent. `XDG_CONFIG_HOME` also appeared without an explanation.                           | The tree now shows files present everywhere, then explains when `snippets.yaml` is added. The environment setting is described in plain words.                                                                                                                                                                        |
| [SSH Connect](ssh-connect.md)                 | A missing OpenSSH client left the user to find the right package; a first-time server fingerprint prompt used security jargon.                                                              | The troubleshooting section includes the Ubuntu/Debian and Fedora client packages, a `ssh -V` check, and restart guidance. The connection steps explain verifying a first-time fingerprint with the server owner. Network access, account credentials and server availability remain prerequisites.                   |
| [Saved Layout](saved-layout.md)               | “OSC 7” and working-directory reporting are unfamiliar, and most shells don't report folders by default.                                                                                    | The guide explains in plain words why folders may reopen at home, and gives copyable startup lines for zsh, bash and PowerShell. It doesn't cover every shell or prompt tool.                                                                                                                                         |
| [Mirror Typing](mirror-typing.md)             | A reader could expect to use a preview that is not packaged or available in the extension catalog.                                                                                          | The guide states that it is source-only, not in the current release, and can send input to several programs. No end-user installation path exists until publication.                                                                                                                                                  |
| [How OMXTerm works](how-it-works.md)          | Internal renderer names and unexplained PTY terminology distract from what the user types and sees.                                                                                         | The overview avoids renderer implementation names and defines PTY as the system connection between OMXTerm and the shell. A short feature tour uses Settings to change text size instead of asking the reader to edit an internal configuration value.                                                                |
| [Linux desktop tips](linux-desktop.md)        | X11/XWayland, HiDPI, VM and graphics-security language can obscure which steps apply to the reader's desktop.                                                                               | The guide defines the display layer, high-resolution display and virtual machine terms, and describes software rendering and its security tradeoff in user terms. Commands remain specific to GNOME, KDE Plasma and Hyprland because desktop settings differ. Other desktop environments need their own instructions. |
| [Linux desktop installer](linux-installer.md) | The commands assume the downloaded files are in the current terminal folder; AppImage and architecture names may be unfamiliar.                                                             | The guide now tells the reader to open Terminal and change to the download folder, defines AppImage and ARM64/x64, and explains what the graphics compatibility switch changes. The x64 helper remains untested and is not presented as qualified.                                                                    |

## Checks that need a real user or computer

A text review cannot establish the acceptance condition that a first-time user can
complete installation and first launch from these pages alone. That needs
walkthroughs on supported macOS ARM64, Linux ARM64 and Windows ARM64 desktops.
The x64 artifacts remain build-only, so documentation cannot turn them into
supported targets. Extension catalog availability likewise does not prove that
every extension action works on every compatible host.
