# Preparatory Linux x64 extension composition

Linux x64 source now admits ordinary production extension management, backend
activation and hosted views through the same owners as Linux/macOS ARM64.
Startup, installation and enablement remain dormant. Explicit shared actions
activate trusted installed packages; disable/uninstall and normal Quit retain
existing owned retirement joins. Infrastructure failure does not prevent terminal
startup. Other unsupported targets retain the explicit unavailable result.

This #712 prerequisite is not a stable SDK or a Snippets migration. Linux x64
retains built-in Snippets and its starter kit. The separate Files native move
addon remains ARM64-only. Published manifests/catalog target restrictions and
immutable releases are unchanged; admitting host infrastructure does not qualify
an existing archive for this target. No automatic installation, activation or
fallback implementation is introduced.

## Installed-package production fixture

On an assigned idle Linux x64 desktop with Electron/native build prerequisites,
build ordinary production output, then run only the opt-in test:

```sh
npm run build
OMXTERM_EXTENSION_COMPOSITION=1 \
  OMXTERM_EXTENSION_COMPOSITION_EVIDENCE=/absolute/external/evidence \
  npm test -- test/integration/extension-production-composition.test.ts
```

The shared macOS/Linux fixture imports `dist/main/index.js` unchanged. Linux uses
X11 and the existing Linux sandbox policy; production startup applies its normal
GPU policy. An authenticated isolated Xvfb/Openbox desktop is suitable for bounded
software-rendered evidence, not hardware-GPU or physical-input qualification.
Do not run desktop tests concurrently.

A real minimal archive with a cooperative backend and editable hosted page
exercises exact-digest local installation/trust, dormant installation/enablement,
explicit activation and backend response, native editing isolated from the PTY,
disable/uninstall and the same usable Surface/PTY. A second backend stays active
until ordinary Quit, which must join both backend streams and the original PTY.
Linux x64 additionally asserts built-in Snippets still opens without extension
activation; macOS retains its absent optional-Snippets management assertion.
The fixture does not install directly into the store or substitute product owners.

## Evidence boundary

The earlier Linux x64 module-native, hosted-view and exact-AppImage packaging
receipts remain separate prerequisites, not evidence of this newly admitted
production lifecycle. Native execution of the shared production fixture is
required before delivery; a skipped opt-in test is not a pass. Record actual
source/archive identities, assertions, captures and process settlement separately.

Scope is source-launched composition with synthetic Chromium input and controlled
consent, not exact-AppImage GUI, public-HTTPS acquisition, physical input,
hardware GPUs, OS-compositor fidelity, full portable checks, Snippets/Files
cutover or publication. Separate WebContents captures do not prove compositor
freshness. Surviving-browser main-death package-file-read exclusion remains
unqualified; normal Quit does not substitute for it. Historical failed campaigns
and diagnostics keep their original identities and limits.
