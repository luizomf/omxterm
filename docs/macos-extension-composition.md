# Preparatory macOS ARM64 extension composition

macOS ARM64 now uses the ordinary production extension management, backend and
hosted-view owners. Settings can install a local archive through captured-byte
trust, or use the existing explicit HTTPS/catalog acquisition paths. Startup,
installation and enablement remain dormant; an explicit shared menu/palette action
activates an enabled package. Disable/uninstall and normal Quit retain the existing
owned retirement joins. Unsupported architectures/Windows retain the explicit
unavailable result; infrastructure failure must not block terminal startup.

This is a bounded prerequisite under #712, **not a stable SDK, publication or
platform-cutover claim**. The prior macOS module-native, hosted-view and exact-DMG
store/lease/bootstrap receipts retain their separate scopes. They do not qualify
this newly admitted production lifecycle. The source-launched fixture below passed
on macOS 27.0.1 ARM64 with Electron 43.8.1, within its stated input and capture limits.

## Preserved boundaries

- macOS retains built-in Snippets, its existing command/shortcut and fresh
  configuration starter kit. The installed package's duplicate action remains
  withheld. Matching Snippets migration and publication are separate #741 work.
- Files' native no-clobber move remains Linux ARM64-only; macOS refuses that
  operation. There is no replacement primitive or macOS Files qualification.
- Published archives/manifests and catalog target restrictions are unchanged.
  Broader host admission does not make a catalog release macOS-compatible.
- Surviving-browser main-death package-file-read exclusion remains unqualified.
  Normal Quit is not a substitute for that experiment. Historical #746 diagnostics
  remain open; do not suppress their output or relax assertions.

## Installed-package production fixture

On an assigned disposable, logged-in, idle macOS ARM64 desktop, build ordinary
production output, then run only the opt-in integration test:

```sh
npm run build
OMXTERM_MACOS_COMPOSITION=1 \
  OMXTERM_MACOS_COMPOSITION_EVIDENCE=/absolute/external/evidence \
  npm test -- test/integration/macos-extension-composition.test.ts
```

The test uses the existing native fixture supervisor and existing PTY/backend/
consent observer. It imports `dist/main/index.js` unchanged, with ordinary
production wiring, rather than rebuilding or substituting application owners.
It installs a real minimal `.omxext` archive generated by
`test/fixtures/macos-composition-package.ts`. The package contains a cooperative
backend echo and a hosted editable page, no Files or Snippets implementation.
The evidence directory retains its exact archive and supervisor receipt/captures.

Assertions cover built-in Snippets availability, exact-digest trust and dormant
installation, explicit menu activation, actual installed backend response in a
native hosted page, child editing isolation, joined disable/uninstall, the same
usable Surface/PTY, and a second active backend joined by ordinary application
Quit. Both backend exit/stream closure and original PTY exit are required before
the successful receipt. No direct package-store installation, alternate platform
switch, mocked backend or test-only production API is used.

Scope is **source-launched production composition**, synthetic Chromium input and
controlled native consent, not physical keyboard/dialog interaction, exact-DMG
GUI execution, notarization, macOS 12 execution or public-HTTPS consumption.
The fixture does not change macOS Chromium sandboxing or select Linux graphics
flags. Its first qualified run completed all five lifecycle assertions with two
exact-digest consents, normal exit, empty captured stderr and joined cleanup.
Separate WebContents captures are not OS-compositor proof. Full formatting,
typecheck and lint passed, with 4,196 headless passes and 66 skips. One complete
independent review found a fixture setup-cleanup issue, corrected separately;
production inputs and scenario assertions were unchanged. A skipped opt-in test
is not a native pass, and these results do not clear historical diagnostics.
