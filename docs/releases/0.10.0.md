# OMXTerm 0.10.0

> Published as the [v0.10.0 GitHub Release](https://github.com/luizomf/omxterm/releases/tag/v0.10.0).
> The exact native artifacts were built and verified from source commit
> `2711f502d45cd86056ce76bffba22e1f8f92499d`, matched to their exact installed

OMXTerm 0.10.0 adds bounded static PNG inline images for direct Live Terminal
Sessions and restores non-black Terminal Theme coverage after the required
xterm beta update. It also includes release metadata, dependency/license, and
public-readiness maintenance completed since the published 0.9.0 release.

## What is new

- **Bounded Pi-compatible Kitty images.** A direct Terminal Surface renders the
  Kitty subset emitted by Pi 0.84.4: transmit-and-display (`a=T`) with PNG
  (`f=100`, `q=2`), optional cell columns and rows, image IDs and cursor movement,
  4,096-character Base64 chunks joined with `m=1` and `m=0`, and image-ID
  (`d=I`), all-image (`d=A`), and all-placement (`d=a`) deletion. The Surface
  reports cell dimensions for `CSI 16 t`.
- **Cell-anchored lifecycle.** Supported images stay anchored through direct
  session scrolling, Terminal Window resizing, Window Font Zoom, tab selection,
  and valid User Configuration Reload. Terminal reset, leaving the alternate
  buffer, and tab disposal release the applicable image resources.
- **Pinned beta pair with explicit controls.** OMXTerm pins `@xterm/xterm`
  `6.1.0-beta.304` and `@xterm/addon-image` `0.10.0-beta.301`. Every Terminal
  Surface enables only Kitty with `pixelLimit: 4_194_304`,
  `kittySizeLimit: 33_554_432`, and `storageLimit: 64`; SIXEL and iTerm2 IIP
  handlers are disabled. The transport target accepts at most 44,739,240 padded
  Base64 characters / 33,554,430 decoded bytes, while storage is approximately
  64,000,000 bytes of canvas-only FIFO accounting.
- **Narrow WebAssembly CSP permission.** Renderer `script-src` adds only
  `'wasm-unsafe-eval'` for the addon's WebAssembly decoder. JavaScript eval,
  remote scripts or images, object sources, network connections, renderer Node
  access, and new preload or IPC capabilities remain forbidden. Image bytes stay
  opaque, memory-only Terminal Payload on the existing PTY output path; there is
  no clipboard, filesystem, logging, download, or application-network expansion.
- **Packaged image runtime and notices.** Native packages are configured to
  include the image addon and byte-matched license texts for the addon and its
  bundled `sixel`, `xterm-wasm-parts`, and `inwasm-runtime` components. Packaged
  verification requires those runtime and license entries.
- **Terminal Theme viewport regression fix.** The beta xterm stylesheet added a
  more-specific opaque black viewport rule. The OMXTerm selector now wins that
  cascade so a non-black Terminal Theme again fills the viewport, native title
  inset, and configured padding across all app-controlled Terminal Window
  content. This restores the existing contract from
  [#231](https://github.com/luizomf/omxterm/issues/231) and
  [#232](https://github.com/luizomf/omxterm/pull/232); it does not enable
  transparency or change the theme schema.

## Compatibility and migration

There are no incompatible schema changes and no manual migration. Version 1
`config.json`, `snippets.json`, and Terminal Theme files accepted by 0.9.0 remain
accepted unchanged. The Terminal Capability Identity also remains
`TERM=xterm-256color`, `COLORTERM=truecolor`,
`TERM_PROGRAM=OMXTerm`, and the installed version in `TERM_PROGRAM_VERSION`.
OMXTerm does not install branded terminfo, Shell Integration, or Pi-specific
environment variables.

Pi 0.84.4 requires explicit Kitty selection until it recognizes OMXTerm. Users
may set `terminal.images` to `kitty` in Pi configuration or launch Pi with
`PI_IMAGE_PROTOCOL=kitty`; OMXTerm does not rewrite that choice. Inline images
are supported only when emitted directly to a Live Terminal Session.

## Known limitations

- Image behavior through tmux, screen, or another multiplexer is unsupported.
  Chafa's raw RGBA Kitty output (`f=32`) remains outside the claimed PNG
  `f=100` subset and is tracked separately in
  [#230](https://github.com/luizomf/omxterm/issues/230). SIXEL, iTerm2 Inline
  Image Protocol, placement IDs, animation, remote sources, downloads,
  persistence, and other unclaimed Kitty paths are unsupported.
- The pinned image beta may show placeholders after FIFO eviction and retains
  documented wrapping and bottom-truncation limitations. Its configured limits
  are not complete memory hardening: decompressed `o=z` output, raw-pixel paths,
  natural PNG dimensions before browser decode, payload Blobs, an
  aggregate-uncapped map of unfinished chunked image IDs, rescaling, Chromium
  codec/canvas allocations, and aggregate use across tabs remain risks. Pi's
  default autoresized 2,000-by-2,000 pipeline is the compatibility target;
  disabling autoresize removes the finite compatibility promise.
- On Linux and Windows, BEL remains silent and marks the ringing session's
  title, but an unfocused Terminal Window does not request native platform
  attention ([#135](https://github.com/luizomf/omxterm/issues/135)).
- The Linux About panel still has incomplete metadata and a missing icon
  ([#134](https://github.com/luizomf/omxterm/issues/134)). Linux native Wayland
  rendering is not claimed; Wayland sessions require XWayland. Normal AppImage
  execution requires kernel FUSE, with `--appimage-extract-and-run` as the
  fallback.
- `windowsShell` selects one executable only and cannot supply arguments,
  profiles, environment expansion, shell syntax, or a wrapper command. Spawn
  permission and executable compatibility are reported only when a future
  session is actually started.
- `wsl.exe` inherits OMXTerm's Windows home as its Initial Working Directory and
  commonly exposes it as `/mnt/c/Users/<user>` instead of the Linux
  distribution's home; OMXTerm does not translate that directory.
- On Windows, every live session counts as Busy because ConPTY cannot expose the
  foreground process name. Electron 43 clipboard Paste can read only one
  Explorer file path; dropping multiple files remains complete and ordered.
- Tabs and Live Terminal Sessions remain ephemeral. Tab order is not saved, and
  tabs cannot move between windows. OMXTerm has no splits, saved or reconnectable
  sessions, Shell Integration, automatic updates, AI assistance, or built-in
  remote terminal features; tmux remains the user's session manager despite not
  carrying the claimed image subset.

## Privacy, security, and publisher identity

Kitty image bytes are untrusted Terminal Payload. They remain memory-only on the
existing PTY-to-renderer path and are never copied to files, clipboard contents,
Operational Events, or application network traffic. OMXTerm itself still makes
no telemetry, analytics, crash-report, update-check, or remote-log requests;
child processes retain their normal operating-system access.

The exact Linux AppImage and Windows installer are unsigned. The macOS
application uses only its required ad-hoc integrity seal. Gatekeeper and
