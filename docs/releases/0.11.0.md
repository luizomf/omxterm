# OMXTerm 0.11.0

[Historical release record](README.md): behavior and evidence below apply to
this version, not current product guidance or release requirements.

[GitHub Release](https://github.com/luizomf/omxterm/releases/tag/v0.11.0)

## Changes

- **Chafa images on all three ARM64 platforms.** Run `chafa -f kitty image.png`
  in a direct Terminal Session. The supported Chafa 1.18.2 raw-RGBA path now
  handles its metadata prelude and standalone completion packet correctly.
- **Windows Kitty transport fixed.** OMXTerm uses the ConPTY DLL already bundled
  with `node-pty`; the system ConPTY could discard image sequences before they
  reached the renderer. A new real-PTY regression covers that transport boundary.
- **Simpler Linux startup.** Linux deliberately uses `--no-sandbox` to avoid
  startup incompatibilities in some environments. Context isolation and the
  minimal preload bridge remain enabled, but do not replace the Chromium
  sandbox. Sandboxed Linux support is outside the current maintenance scope;
  simple, reproducible contributions are welcome. See [ADR 0024](../adr/0024-disable-the-chromium-sandbox-on-linux.md).
- **More reliable native verification.** Windows checks now exercise the exact
  NSIS installation and payload with explicit disposable-VM consent and guarded
  cleanup. Chromium graphics fixtures use non-activating visible windows on
  Windows and Linux so real image-frame progress is observed.

No User Configuration migration is required. Linux's reduced Chromium sandbox
protection is an intentional platform-policy change; macOS and Windows retain
Chromium sandboxing. The optional Linux installer remains ordinary-user-only.
No administrator sandbox setup or global OS-policy change is required.

Images remain unsupported through tmux, screen or another multiplexer. Chafa
requires explicit `-f kitty`; automatic recognition of OMXTerm is not claimed.
The pinned Kitty subset, image limits and known memory-accounting gaps remain
as described in the [usage guide](../usage.md#inline-terminal-images) and
[product contract](../spec.md#terminal-behavior). x64, Intel macOS, native Wayland,
additional image protocols and package formats remain unsupported.

Gatekeeper/SmartScreen presentation, native desktop-shell integration outside
verified installation seams, and Windows OS-token sandbox properties remain
**UNVERIFIED** by automation. Successful startup and renderer preferences do not
constitute an independent OS-security audit.

## Platform warnings

The macOS application has a verified ad-hoc integrity seal, but no Apple
Developer ID signature or notarization. macOS may warn that it cannot verify the
developer or check the app for malicious software. Review the source, verify
the SHA-256 and proceed only if you trust this exact artifact. Follow Apple's
[Open Anyway instructions](https://support.apple.com/102445) for this application;
do not disable system-wide macOS protections.

The Windows installer is unsigned and may trigger Microsoft Defender SmartScreen's
unknown-publisher warning. Verify the SHA-256 and proceed only if you trust this
exact file. `More info -> Run anyway` applies to this installer only; do not
disable SmartScreen or other system-wide Windows protections.

These are maintainer-published open-source builds, not independently audited,
approved by a platform vendor or guaranteed free of defects.
