## Material changes since 0.11.0

- **Restty is the sole Terminal Surface.** OMXTerm now uses pinned Restty 0.3.0
  and its pinned Ghostty core in development and packaged applications. A real
  WebGL2 backend, the tracked core and fonts must initialize before the PTY
  starts. There is no renderer selector, software renderer or fallback Surface.
- **Font and spacing behavior is explicit.** The default Terminal Font Stack is
  bundled FiraCode Nerd Font Mono regular/bold, DejaVu Sans Mono regular/bold,
  retained JetBrainsMono Nerd Font Mono coverage, then operating-system emoji,
  CJK and symbol fallbacks. Font family and line height are creation-time values
  for an existing Surface; theme, font size, programming ligatures, padding and
  scrollback apply live. Programming ligatures default to enabled and can be
  changed with `font.ligatures`.
- **Scrollback follows the pinned Ghostty core.** A positive
  `scrollback.lines` value is an approximate physical-history target because
  eviction uses whole pages. An independent 10,000,000-byte core ceiling may
  retain fewer rows. Zero immediately selects the no-history path. These are
  per-session limits, not a total process-memory claim.
- **Terminal interaction moved to the Restty seam.** Protected Paste, write-only
  OSC 52, selection/copy, visible HTTP(S) links, titles, bells, Option Key Mode,
  direct Pi/Chafa Kitty images, mouse reporting and capability replies retain
  their OMXTerm host policies. Visible destinations now underline while the
  activation modifier is held.
- **Bounded local image preview.** A native picker, authority-free absolute
  `file:///` URL or unambiguous native absolute path can preview one local
  static PNG/JPEG. Reads occur only after explicit activation on the machine
  running OMXTerm and are bounded to 16 MiB encoded, 8192 pixels per side and
  16 million pixels. Relative, SSH-remote, UNC/device, OSC 8 and HTTP image
  sources are not inferred or fetched. This is separate from direct-session
  Kitty images carried as Terminal Payload.
- **Output and resource ownership are bounded more precisely.** PTY output uses
  cumulative sender/session-validated acknowledgements with high/low
  watermarks; unfinished OSC/CSI controls are bounded; fonts are shared only
  within one renderer window generation and released with their leases. These
  controls do not constitute a total RAM, browser-resource or GPU-memory bound.
- **Local Developer Tools action.** `View -> Toggle Developer Tools` opens the
  selected window's local tools without remote debugging. Developer Tools can
  expose Terminal Payload and runtime state and must be redacted before sharing.

Restty is prominently credited in the [README](../../README.md), and complete
runtime/font provenance is recorded in [Third-Party Notices](../../THIRD_PARTY_NOTICES.md),
the [Restty guide](../restty-development.md) and the bundled font source record.
The retained xterm.js visible-link expression, `text-shaper` FreeType-derived
portions and Nerd Fonts patched glyph sets keep their required copyrights,
licenses and pinned provenance in every package.

## Compatibility and migration

User Configuration and Terminal Theme schemas remain at `"version": 1`.
Existing 0.11.0 configuration and theme files remain valid. The default family
changes from JetBrainsMono Nerd Font Mono to FiraCode Nerd Font Mono with real
regular/bold faces and a broader bundled coverage stack, so glyph metrics and
native rasterization can look different.

`font.ligatures` is an optional compatible schema-v1 addition. **Before
downgrading to 0.11.0, remove `font.ligatures` from `config.json`** because that
version correctly rejects unknown keys. OMXTerm never edits or migrates the
file. A changed `font.family` or `font.lineHeight` requires restart to reach
Surfaces that already exist; `font.ligatures` applies live.

No package-format migration is required. The Supported Platforms remain macOS
ARM64 DMG, Linux ARM64 AppImage plus optional per-user installer, and Windows
ARM64 NSIS. This specific preparation contains no Windows 0.12.0 candidate after
its native gate failed; diagnosis is deferred to issue #310, while Windows
0.11.0 remains available. x64 and Intel macOS remain unsupported.

## Platform limits and unverified risk

- Native glyph rasterization varies by operating system and GPU. Pixel-identical
  appearance and human visual acceptance are not claimed. The prior Windows
  functionality observation was not an appearance acceptance.
- macOS alone requests Dock attention for BEL in an unfocused window. Linux and
  Windows retain the title marker but have no equivalent native attention
  request yet (issue #135).
- Local Image Preview paths always name files on the OMXTerm host. Inline Kitty
  images are a pinned direct-session Pi/Chafa subset; tmux/screen passthrough,
  other image protocols and remote/filesystem Kitty sources remain unsupported.
- Linux defaults to X11 and needs XWayland in a Wayland session. Native Wayland
  is not claimed. Linux runs unconditionally with `--no-sandbox`; context
  isolation, disabled Node integration and the typed preload bridge remain but
  are not equivalent sandbox protection. See [ADR 0024](../adr/0024-disable-the-chromium-sandbox-on-linux.md).
- Gatekeeper/SmartScreen presentation, native visual output and desktop-shell
  behavior outside automated seams remain **UNVERIFIED** where automation
  cannot observe them. Missing human testing is not converted into a pass.

The macOS app is ad-hoc sealed for bundle integrity but has no Apple Developer
ID signature or notarization. macOS may warn that it cannot verify the developer
or check the app for malicious software. After verifying the published checksum, users who trust that exact
artifact should follow Apple's
[Open Anyway instructions](https://support.apple.com/102445); do not disable
system-wide macOS protections.

The Linux AppImage is unsigned and carries no verified publisher identity. The
published macOS/Linux builds are maintainer-produced open-source artifacts, not
independently audited or approved by Apple or another platform vendor and not
guaranteed defect-free. There is no Windows 0.12.0 installer; the unchanged
published 0.11.0 Windows warning and provenance remain in its
[release record](0.11.0.md#platform-warnings).
