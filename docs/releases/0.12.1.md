0.12.1 brings compatible rendering and font-loading corrections to macOS and

## Changes

### Compatible corrections since macOS/Linux 0.12.0

- **Smaller Apple emoji shaping input.** Main skips Apple Color Emoji's unused
  `sbix` bitmap table using bounded positional reads before validation and IPC.
  Every face and other table is retained; native Canvas still uses the unchanged
  installed font. This reduces font-byte costs, not a guaranteed total RSS or
  GPU-memory budget. The existing blank-emoji fallback when native Canvas is
  unavailable is not fixed. See the [bounded comparison](../emoji-shaping-experiment.md).
- **Hidden tabs stop rendering without postponing reveal.** Hidden Terminal
  Surfaces no longer clear, draw or upload render data, including when mounting
  finishes while hidden. Output ingestion, ordered ACKs, replies, titles, bells
  and scrollback continue. Hidden geometry does not resize the PTY. Selection
  refits and redraws current content and cursor before visible presentation;
  hidden image deletion/reset/disposal releases disposable renderer resources.
  Synchronized-output batching remains intact. No fixed CPU reduction or
  whole-application memory saving is claimed. See [rendering evidence](../hidden-rendering-evidence.md).
- **Unused WebGL depth attachment removed.** The WebGL2 context requests
  `depth:false`; text, selection, images and lifecycle behavior retain their
  existing contracts. The measured attachment removal is not a quantified RAM
  saving. See [depth evidence](../webgl-depth-evidence.md).
- **Appearance verification observes selection and frame progression.** #310
  replaces a test-only 100 ms assumption with public copy observation into a
  memory sink and real animation-frame progression before capture. A delayed-frame
  regression demonstrated capture-before-render ordering. It is not a product
  selection-color change or proof of the original historical VM trigger; that
  trigger remains **UNVERIFIED**. Pixel assertions remain the rendering oracle,
  not a claim that two animation frames universally fence a compositor.
- **Configured-font verification waits for remounted output frames.** During
  #320 Linux qualification, diagnostic captures showed an empty regular row
  followed by a painted bold row, while the reference captured both. A controlled
  delayed-output-frame regression reproduced incomplete capture. The fixture
  now crosses real frames after each remount's output instead of assuming
  100 ms establishes readiness, and checks exact configured/reference bitmap
  equality in every DPR and delayed-frame case. This is a test-ordering
  correction, not a product-font change; the original uninstrumented full-suite
  occurrence's precise trigger remains unproven.

These are compatible corrections within the 0.12 contract, not new capabilities.
The existing spec and ADRs govern; this preparation changes neither.

### Windows catch-up from its published 0.11.0

Windows 0.12.1 now has its own complete native qualification, including the
exact NSIS installation seam. Its changed-boundary baseline includes the
complete 0.12 transition, not just the corrections above:

- Restty 0.3.0 and its pinned Ghostty core replace xterm as the sole Terminal
  Surface. Working WebGL2, core and fonts must initialize before a shell starts;
  there is no selector, software renderer or fallback Surface. Irrecoverable
  context loss fails and cleans only the owning session.
- FiraCode Nerd Font Mono regular/bold becomes the default, followed by DejaVu
  Sans Mono regular/bold, retained JetBrainsMono Nerd Font Mono and native
  fallbacks. Configured-family precedence, bounded native-font IPC and
  window-generation sharing preserve ownership across concurrent tab creation.
  Programming ligatures are configurable and enabled by default. Theme,
  geometry, viewport, selection and grapheme behavior use the Restty seam.
- Positive scrollback targets approximate physical history through whole-page
  eviction, with an independent 10,000,000-byte ceiling; zero disables history.
  Keyboard input and delivered paste/snippet/path input return to the live
  cursor; output alone, focus and cancelled paste do not.
- Protected Paste, write-only OSC 52, titles, bells, direct Pi/Chafa images,
  capability replies, mouse reporting and visible-link activation retain
  OMXTerm host policy. Modified hover underlines visible destinations. Ordered
  output ACKs and unfinished-control bounds do not establish total memory limits.
- Explicit Local Image Preview adds a picker and literal local `file:///` or
  native absolute-path activation for static PNG/JPEG, bounded to 16 MiB encoded,
  8192 pixels per side and 16 million pixels. It reads only on the OMXTerm host
  after explicit activation, never by inferring remote files or a shell cwd.
- `View -> Toggle Developer Tools` affects only the selected window, without
  enabling remote debugging. Tools may expose private Terminal Payload and
  runtime state; redact diagnostics before sharing.
- Fresh prepared dependencies, packaged parsed-output proof and current bundled
  licenses passed alongside exact NSIS payload equality, installed startup and
  owned cleanup, not merely an unpacked application.

The [0.12.0 notes](0.12.0.md#material-changes-since-0110) and
[Restty cutover evidence](../restty-cutover-evidence.md) retain the earlier batch
history; they are not substitutes for Windows 0.12.1 evidence.

## Compatibility and migration

There is no incompatible change or required migration from 0.12.0. User
Configuration and Terminal Theme remain schema version 1. Existing 0.11.0
configuration/theme files remain accepted when upgrading Windows, but the
Restty transition changes the default font, glyph metrics and scrollback
retention as described above. Font family and line height require restart for
existing Surfaces; theme, size, programming ligatures, padding and scrollback
apply live. OMXTerm never rewrites or migrates user files.

**Before downgrading to 0.11.0, remove `font.ligatures` from `config.json`.**
That optional schema-v1 key was added in 0.12; 0.11 correctly rejects unknown
keys. No package-format migration is required: DMG, AppImage plus optional
per-user helper, and NSIS remain the ARM64 formats. x64 and Intel macOS remain
unsupported. Windows requires the Visual C++ Redistributable for ARM64.

## Provenance and installation warnings

OMXTerm for Apple Silicon is intentionally not signed with an Apple Developer
ID and is not notarized. macOS may warn that it cannot verify the developer or
check the app for malicious software. Review the source, verify the published
SHA-256, and proceed only if you trust that exact artifact. If you choose to
open it, follow Apple's current
[Open Anyway instructions](https://support.apple.com/102445) in System Settings
-> Privacy & Security. Do not disable system-wide macOS security protections.

The Linux AppImage is unsigned and provides no verified publisher identity.
The optional helper consumes only a previously verified local AppImage; it does
not download, establish publisher trust or make system-wide changes.

OMXTerm for Windows ARM64 is intentionally not signed with a code-signing
certificate. Microsoft Defender SmartScreen may warn that the installer is from
an unknown publisher. Review the source, verify the published SHA-256, and
proceed only if you trust that exact artifact. If you choose to install it,
use SmartScreen's `More info -> Run anyway`
for this one file. Do not disable SmartScreen or other system-wide Windows
security protections.

These are maintainer-produced open-source builds, not independently audited,
approved by Apple, Microsoft or another platform vendor, or guaranteed free of
defects in all code and dependencies. Restty, Ghostty, text-shaper and bundled
font attribution remain in [Third-Party Notices](../../THIRD_PARTY_NOTICES.md).
The explicit acceptance and publication authority are recorded in #323, not
inferred from these provenance statements.
