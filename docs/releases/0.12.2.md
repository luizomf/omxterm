# OMXTerm 0.12.2

[Historical release record](README.md): behavior and evidence below apply to
this version, not current product guidance or release requirements.

**Published:** [OMXTerm 0.12.2](https://github.com/luizomf/omxterm/releases/tag/v0.12.2),
September 20, 2026. The owner accepted the eight identities below after native
verification and independent final review, and separately authorized publication
in #334. All eight published downloads matched their accepted sizes and SHA-256,
including the four checksum records. The published files remain unchanged.

## Changes

Fixes persistent Neovim/TUI display corruption after Window Font Zoom and User
Configuration Reload (#327, PR #329). The terminal now delivers the negotiated
DEC 2048 in-band resize notification promptly after Adapter resize, with
complete-cell pixel geometry. The correction preserves the existing session;
it does not disable the protocol, special-case Neovim, or require tmux.

There are no intentional incompatible changes, schema changes, or migrations.
Native regression coverage also accounts for successive real layout changes and
fractional display scaling without changing product rounding behavior.

## Optional observations and remaining risk

The maintainer reported the preceding development correction working on ARM64
macOS, Ubuntu 26.04 LTS (GNOME), Fedora 44 (KDE Plasma), Fedora 44 (GNOME), and
Windows 11. These are historical development-build observations, not manual
acceptance evidence for the rebuilt final artifacts. No manual retest is required.

Physical Linux/Windows GPU behavior and Gatekeeper/SmartScreen presentation are
**UNVERIFIED** by these release checks. VM native rendering is not qualification
of every physical GPU or desktop environment.

Unresolved follow-ups are not fixed by this release: installed-font rejection
(#328), tentative Linux mouse-selection behavior (#331), Ctrl shortcut handling
through VM/remote-input environments (#332), and a Windows Bash bell-related
flash of undetermined origin (#333).

## Platform limitations and provenance

OMXTerm for Apple Silicon is intentionally not signed with an Apple Developer
ID and is not notarized. macOS may warn that it cannot verify the developer or
check the app for malicious software. Review the source, verify the published
SHA-256, and proceed only if you trust this exact artifact. If you choose to
open it, follow Apple's current [Open Anyway instructions](https://support.apple.com/102445)
in System Settings -> Privacy & Security. Do not disable system-wide macOS
security protections. This is a maintainer-published open-source build; it is
not independently audited, approved by Apple, or guaranteed free of defects in
all code and dependencies.

Linux uses X11/XWayland and the documented unconditional Linux-only
`--no-sandbox` policy ([ADR 0024](../adr/0024-disable-the-chromium-sandbox-on-linux.md)).
The ARM64 AppImage is unsigned. Kernel-FUSE mounting is host-dependent;
`--appimage-extract-and-run` is the extraction fallback, not a sandbox fix.
The native verifier exercises extraction fallback and conditionally direct
kernel-FUSE startup when its installation-time probe establishes availability.
The final Ubuntu run passed with 8 operational events; this does not establish
FUSE availability on another machine.

OMXTerm for Windows ARM64 is intentionally not signed with a code-signing
certificate. Microsoft Defender SmartScreen may warn that the installer is
from an unknown publisher. Review the source, verify the published SHA-256,
and proceed only if you trust this exact artifact. If you choose to install
it, use SmartScreen's `More info -> Run anyway` for this one file. Do not
disable SmartScreen or other system-wide Windows security protections. This
is a maintainer-published open-source build; it is not independently audited,
approved by Microsoft, or guaranteed free of defects in all code and
dependencies.
