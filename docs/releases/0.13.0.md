# OMXTerm 0.13.0

This release improves how configured fonts look and share resources across
tabs. It also adds clearer Windows Bash troubleshooting to the installation
guide. No configuration migration is needed.

Published: [OMXTerm 0.13.0](https://github.com/luizomf/omxterm/releases/tag/v0.13.0),
September 21, 2026. All exact artifacts below were **OWNER ACCEPTED** and
publication was separately **AUTHORIZED** in #346. Every downloaded asset
matched its accepted size and SHA-256 after publication.

## Changes

- Configured installed font families now use their real bold, italic and
  bold-italic faces when available. Missing styles retain synthetic fallback;
  collection faces share source bytes and parsed resources across styles/tabs.
- Synthetic bold strengthens horizontal and vertical strokes. Additional
  synthetic ink stays within terminal cells, including synthetic italic. Real
  styles, regular rendering, ANSI colors and cell geometry remain unchanged.
- Linux ignores Fontconfig-simulated optional style patterns rather than
  rejecting an otherwise valid regular family.

There are no intentional incompatible changes, schema changes or migrations.
The bundled fallback stack remains intact, including its existing character
coverage. This release does not promise pixel parity with other terminals.

### Windows Bash visual bell

Git Bash configurations with Readline's `bell-style visible` can produce a
bright full-terminal flash, for example when Backspace is pressed at an empty
prompt. The visual-bell capability requests screen color inversion, not an
ordinary BEL notification. Version 0.13.0 does not contain a product-side fix.

Run `bind 'set bell-style none'` in the affected Bash session for immediate
relief. The [Windows installation guide](../../README.md#bright-flashes-in-bash)
explains how to persist the setting in `~/.inputrc` while preserving other shell
settings. This is an optional user configuration change, not an automatic
installer modification. Product-side investigation remains open in #333 to
reduce first-use friction without breaking legitimate terminal behavior.

### Platform security and operating requirements

macOS is ad-hoc sealed for bundle integrity, not Developer ID signed or
notarized. If macOS blocks an accepted artifact, review its source and SHA-256
and use Apple's [Open Anyway instructions](https://support.apple.com/102445)
only if you trust that exact file. Do not disable system-wide protections.

Linux requires X11/XWayland and uses the unconditional Linux-only
`--no-sandbox` policy in [ADR 0024](../adr/0024-disable-the-chromium-sandbox-on-linux.md).
Its AppImage is unsigned. Kernel-FUSE availability is host-dependent;
`--appimage-extract-and-run` is the extraction fallback, not a sandbox fix.

Windows ARM64 NSIS is unsigned and may trigger SmartScreen's unknown-publisher
warning. Review source and SHA-256 before trusting a file; use `More info -> Run
anyway` only for that exact accepted installer. Do not disable SmartScreen or
other system-wide protections. No platform package has a verified publisher
identity or an independent security-audit guarantee.
