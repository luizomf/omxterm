# OMXTerm 0.14.0

[Historical release record](README.md): behavior and evidence below apply to
this version, not current product guidance or release requirements.

This release adds a window-local tab-bar toggle and gives the terminal more
space in native macOS fullscreen. It also fixes local-image sizing, keyboard
shortcut delivery, selection, installed-font discovery and native window
attention. No configuration migration is required.

Published: [OMXTerm 0.14.0](https://github.com/luizomf/omxterm/releases/tag/v0.14.0),
September 22, 2026, at `23:37:44Z`. The owner accepted the eight exact files
below and separately reaffirmed publication authorization in #377. Final
independent Standards/Spec review passed without surviving findings. All eight
published downloads matched their accepted sizes and SHA-256.

## Changes

- Toggle the selected window's tab bar with `Cmd+Shift+B` on macOS or
  `Ctrl+Shift+B` on Linux/Windows. The setting is temporary and per-window;
  hiding the bar preserves tabs and sessions. The action is remappable as
  `toggleTabBar`.
- Native macOS fullscreen removes the app's windowed title inset while
  preserving configured terminal padding; leaving fullscreen restores it.
- Local image previews fit proportionally inside the overlay, including after
  resizing and at fractional display geometry.
- Shifted punctuation shortcuts are handled before terminal input, and desktop
  selection tolerates mixed pointer identities.
- Installed regular font discovery accepts the documented exact native family
  names while retaining strict face validation.
- Terminal BEL requests and resets native window attention. Linux and Windows
  About dialogs show the product's metadata and icon.
- Development dependency fixes, bounded native-fixture cleanup, documentation
  improvements and a macOS privacy-identity investigation are included.

There are no intentional incompatible configuration/schema changes or required
migrations. The privacy investigation is a bounded proposal, not an implemented
signing fix: release packaging remains ad-hoc and permissions may need renewed
approval after replacing macOS builds.

## Remaining risks and limitations

- Native VM tests do not qualify every physical GPU or desktop environment.
  Gatekeeper/SmartScreen presentation and behavior beyond automated native
  seams remain unverified unless separately observed. Manual testing is optional.
- macOS privacy retention is not guaranteed by this release. The investigation
  observed only specific operations with a private experimental identity; that
  identity is not used by these release artifacts.
- Bash configurations using Readline's visible bell can still flash the entire
  terminal. Native BEL attention is a different mechanism, not a visual-bell
  fix. The installation guide's optional `bell-style none` workaround remains.
- Linux requires X11/XWayland and uses the fixed Linux-only `--no-sandbox`
  policy in [ADR 0024](../adr/0024-disable-the-chromium-sandbox-on-linux.md).
  The AppImage is unsigned; `--appimage-extract-and-run` is the fallback
  when kernel-FUSE mounting is unavailable, not a sandbox repair.
- No package has a verified publisher identity or an independent security-audit
  guarantee.

### Gatekeeper and provenance

OMXTerm for Apple Silicon is intentionally not signed with an Apple Developer
ID and is not notarized. macOS may warn that it cannot verify the developer or
check the app for malicious software. Review the source, verify the published
SHA-256, and proceed only if you trust this exact artifact. If you choose to
open it, follow Apple's current [Open Anyway instructions](https://support.apple.com/102445)
in System Settings -> Privacy & Security. Do not disable system-wide macOS
security protections. The application has an ad-hoc integrity seal, not a
verified publisher identity.

### SmartScreen and provenance

OMXTerm for Windows ARM64 is intentionally not signed with a code-signing
certificate. Microsoft Defender SmartScreen may warn that the installer is
from an unknown publisher. Review the source, verify the published SHA-256,
and proceed only if you trust this exact artifact. If you choose to install
it, use SmartScreen's `More info -> Run anyway` for this one file. Do not
disable SmartScreen or other system-wide Windows security protections.
