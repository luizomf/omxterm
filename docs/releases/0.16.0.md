## Changes

- Configure initial title-bar and tab-bar visibility with `window.showTitleBar`
  and `window.showTabBar`, both defaulting to `true`. The enabled tab strip
  appears only with two or more tabs.
- Toggle the current title area through View → Toggle Title Bar or remappable
  `Cmd+Shift+D` / `Ctrl+Shift+D`, preserving the window, Terminal Surfaces and
  PTYs. Configuration initializes new windows; reload preserves current choices.
- macOS retains blended native traffic lights and a 30 px inset. Linux and
  Windows use a themed, hideable 34 px custom title row in a frameless window,
  with native operations and guarded Busy Session closure.
- With the title hidden, hovering within the top 150 logical pixels reveals a
  centered 90×14 logical-pixel native drag handle. Only the handle is a drag
  target; hover does not move layout or refit PTYs. Preview/fullscreen guards
  preserve existing sessions.
- On Linux and Windows, standalone **Alt press/release opens the native
  application menu as a popup**, retaining its hierarchy, actions and effective
  shortcuts. Its anchor is 8 logical pixels from the left content edge and 8
  below the visible title row, or 8 from the top when hidden/fullscreen.
  This replaces the former horizontal menu-bar presentation, which Electron
  cannot supply in frameless windows. Native navigation/dismissal, ordinary Alt
  combinations and AltGr remain distinct. macOS menus and Option input are unchanged.
- Refresh the bundled omtheme palette's twelve ANSI/bright values and two
  selection values. Existing user-owned theme/configuration files are not
  rewritten; their copies remain under the user's control.
- Accepted Quit stops new session starts and waits for actual exits of all
  owned native PTYs, including sessions whose windows already closed. Busy
  confirmation still precedes shutdown.

Existing configuration remains valid; no configuration/theme schema migration
is required. The Linux/Windows Alt menu intentionally changes presentation as
noted above, without requiring a configuration change. No new runtime dependency,
application-window blur or translucency is included.

- macOS has an ad-hoc integrity seal, no Developer ID and no notarization.
  Linux/Windows are unsigned. No artifact has a verified publisher identity or
  independent security-audit guarantee. Follow the per-file
  [Gatekeeper and SmartScreen guidance](../release.md#gatekeeper-and-provenance-note)
  only if you trust the exact checksum; never disable system-wide protection.
- Linux requires X11/XWayland and its fixed `--no-sandbox` policy. Native
  Wayland and physical Linux dragging remain **UNVERIFIED**.
  `--appimage-extract-and-run` remains the fallback when FUSE is unavailable.
- Targeted native popup input/pixels were verified on the identical candidate
  tree: Linux used actual production UI; Windows used production modules with a
  synthetic content surface, alongside the real PTY/Surface integration fixture.
  These are not physical-keyboard/layout coverage or exact-package manual tests.
  The owner-approved Fedora prototype is likewise not substituted for package proof.
- Exact-artifact physical gestures, macOS traffic-light/fullscreen interaction
  and first-download trust/privacy prompts remain **UNVERIFIED**. Ad-hoc identity
  changes may require renewed privacy approvals.
- Historical Fedora ownership-registration failure #405 and earlier Windows
  prompt/native-crash/preparation occurrences remain causally unresolved. Current
  passing runs do not establish that every intermittent mechanism was eliminated.
- Packaged probes require parsed positive cell dimensions and a nonempty
  `TERM_PROGRAM_VERSION`; their compact receipts do not retain every numeric
  dimension or the literal live version string. Version metadata is separately
  verified. Probe group termination is not production Quit coverage.
