## Changes since 0.18.0

- Local Image Preview recognizes quoted paths with spaces, home shorthand,
  relative image references and line/column suffixes. Relative references ask
  for a base folder on every activation; nothing infers a shell's working
  directory. Paths always name files on the machine running OMXTerm, including
  when their text came from SSH. Preview still supports only bounded static PNG
  and JPEG files; recognizing a `.webp` name does not add WebP support.
- Closing a tab after confirmation retains the original target. Removing a
  background tab preserves the selected tab and input destination.
- Tabs still initializing keep their window alive while sibling sessions exit.
  Cancellation releases partial rendering resources without starting a late
  session or reporting a false failure.
- Native executable-start failures are reported distinctly from programs that
  successfully start and exit nonzero. Failure dialogs retain their owning tab
  and window until acknowledgement, independently of sibling exits.
- Font reload notices retain each Surface's creation-time family/line height,
  including Surfaces still initializing. Startup tab titles reconcile correctly.
- Windows restores the native drag handle after leaving fullscreen. Linux native
  tests now account for the production X11 relaunch and explicitly declared
  compositor maximize policy without weakening the default native behavior.
- Empty unknown keys are rejected consistently in configuration, themes and
  snippets. Installation, onboarding and native-development guides are clearer.

Configuration, theme and snippet schemas remain version 1. **No manual migration
is required for valid files.** An empty unknown key (`""`) was never supported;
files relying on its previous accidental acceptance now receive a validation
error and should have that key removed. Existing user files are not rewritten.

## Changed boundaries and verification

| Boundary                                                                                      | Automated evidence                                                                                |
| --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Local-image recognition, explicit activation, filesystem/IPC validation and PNG/JPEG decoding | Reference unit tests, native image loader/decoder fixtures and real Restty modified-click routing |
| Tab close target, selection, pending initialization and failure acknowledgement               | Unit ownership tests and native real-PTY/window/dialog fixtures                                   |
| Native executable startup versus ordinary nonzero exit                                        | Guarded node-pty preparation and real missing-executable/default-shell native regressions         |
| Creation-time fonts, initialization cancellation and startup titles                           | Ownership unit tests and dedicated native Surface/PTY fixtures                                    |
| Windows fullscreen drag handle and Linux relaunch/window policy                               | Platform-native Window Chrome and About fixtures                                                  |
| Strict schema keys and version consistency                                                    | Schema regression tests, native build and exact-package version/content/startup checks            |

Native fixture coverage is not physical manual acceptance. Image-picker selection
is controlled at the dialog port; native failure dialogs are acknowledged through
the fixture API. Exact packages receive the packaged Surface/PTY startup proof,
not a claim that every regression fixture ran inside each installer.

## Limits and provenance

All packages are ARM64 only and have no verified publisher identity. macOS uses
an ad-hoc integrity seal, not Apple Developer ID signing or notarization.
Windows is unsigned. Linux retains the fixed `--no-sandbox` policy, with context
isolation still enabled; native Wayland is not claimed.

macOS Gatekeeper may warn that it cannot verify the developer or check the app
for malicious software. Review the source and verify the checksum; only if you
trust the exact artifact, follow Apple's
[Open Anyway instructions](https://support.apple.com/102445) in
**System Settings → Privacy & Security**. Do not disable system-wide protections.
The ad-hoc seal establishes integrity, not publisher trust.

Windows Defender SmartScreen may warn about an unknown publisher. Review the
source and verify the checksum; only if you trust the exact installer, use
**More info → Run anyway** for that file. Keep Defender and SmartScreen enabled.

UNVERIFIED: first-download Gatekeeper/SmartScreen interaction; physical
image-picker selection and failure-dialog acknowledgement; visible blur across
all desktops and older macOS versions; universal GPU/compositor compatibility.
Manual testing is optional and no new manual coverage is claimed. Windows
old-version replacement is also UNVERIFIED for this exact installer because the
native verification environment had no prior installation.

Dependency audit warnings remain for development-only `fast-uri` and `undici`
transitive dependencies. They were recorded without changing the locked build
inputs; successful native checks are not a clean security-audit claim.
