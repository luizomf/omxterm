> Published 2026-07-19: the accepted `OMXTerm-0.2.0-arm64.dmg` (SHA-256
> `8af7122f93e58553da61fcd3dc000a3ec3296f81762face449c7d88846f29b58`) is
> attached to the [v0.2.0 GitHub Release](https://github.com/luizomf/omxterm/releases/tag/v0.2.0),
> built from source commit `5800ffb6aed7da71e0c67cd0fb59aff9292c10f4`.

## What is new

OMXTerm 0.2.0 adds three user-visible capabilities on top of 0.1.0:

- **Resilient startup.** An invalid `config.json` or Terminal Theme file no
  longer stops OMXTerm from opening. The application starts with its built-in
  defaults for whatever failed, reports the exact problem on stderr and in a
  persistent, non-blocking in-app error surface, and leaves the file
  untouched, so the file can be fixed inside OMXTerm itself. Fallback is
  always to built-in defaults, never to a cached configuration.
- **Configurable keybinds.** An optional `keybinds` preference in
  `config.json` remaps the application-menu shortcuts (`quit`, `copy`,
  `paste`, `selectAll`, `newWindow`, `closeWindow`, `zoomIn`, `zoomOut`,
  `actualSize`, `toggleFullScreen`, `toggleSnippets`). The menu displays the
  effective accelerator; duplicate accelerators are judged on the effective
  map and rejected loudly.
- **Snippets Sidebar.** An optional read-only `snippets.json` next to
  `config.json` defines user snippets shown in a per-window sidebar
  (`Cmd+Shift+S` by default). Search filters by name and description; a click
  injects the snippet through the same protected-paste path as a normal
  paste, and `execute: true` snippets additionally submit with Enter. The
  file is reread each time the sidebar opens.

## Incompatible change

0.2.0 intentionally revises one published 0.1.0 contract sentence: invalid
user files no longer stop startup, and a selected external theme that fails to
load now falls back — loudly — to the bundled `omtheme` instead of blocking
the application. Validation strictness, the precise diagnostics, and the
guarantee that user files are never modified are unchanged. No user action or
migration is required: files that were valid under 0.1.0 behave identically,
and files that previously blocked startup now produce a running application
plus a persistent error.

## Supported Platform

The only Supported Platform is Apple Silicon (`arm64`) on Otávio's current
macOS environment. Intel Macs and other operating systems are not supported by
this version.

## Known limitations

- OMXTerm has no tabs, splits, saved or reconnectable sessions, profiles,
  Shell Integration, automatic updates, AI assistance, or built-in remote
  terminal features. Closing a Terminal Window ends its Live Terminal
  Session; tmux remains the session manager.
- User Configuration and external Terminal Theme changes require a restart.
  Snippets are the exception: `snippets.json` is reread each time the
  Snippets Sidebar opens, without file watching or live reload.
- Keybinds cover the fixed application-menu action vocabulary only: no new
  actions, system-global shortcuts, chords, or per-platform maps. Snippets
  have no in-app editing, variables, placeholders, or sync.
- Distribution is Apple Silicon-only and intentionally unsigned and not
  notarized. The release process requires manual verification of one exact
  DMG before any publication can be authorized.

## Compatibility and migration

Version 1 `config.json` and Terminal Theme files from 0.1.0 are accepted
unchanged; `keybinds` and `snippets.json` are optional additions to the same
version 1 schemas. The only behavioral difference for existing files is the
resilient failure handling described above, which requires no migration.
