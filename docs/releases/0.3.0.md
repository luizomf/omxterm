# OMXTerm 0.3.0

Published 2026-07-20 as the [`v0.3.0` GitHub Release](https://github.com/luizomf/omxterm/releases/tag/v0.3.0),
built from commit `12cd5810b6ff03aaf62445d4bc60b2e623a65145`. The accepted
Release Artifact is `OMXTerm-0.3.0-arm64.dmg` (122936033 bytes, SHA-256
`336343ebfb14120aea02d5ad729e313856e63da7235006c6afed9cb8582ec54e`).

## Known issue

The default `Ctrl+Tab` and `Ctrl+Shift+Tab` tab-cycling shortcuts do not work
in this release ([#82](https://github.com/luizomf/omxterm/issues/82)): macOS
does not deliver `Control+Tab` to menu key equivalents, so the `nextTab` and
`previousTab` defaults never fire and the shell receives a plain Tab. All
`Cmd`-based tab shortcuts work. Workaround: remap both actions in
`config.json` to `Cmd`-based accelerators, such as
`"keybinds": { "nextTab": "Command+Alt+Right", "previousTab": "Command+Alt+Left" }`.

## What is new

OMXTerm 0.3.0 adds Terminal Tabs on top of 0.2.0:

- **Tabs.** A Terminal Window now holds one or more Terminal Tabs, each owning
  exactly one Live Terminal Session. `Cmd+T` creates a tab in the selected
  window while `Cmd+N` keeps creating independent windows. The tab strip is an
  OMXTerm-drawn full-width row below the fixed 30 px title inset and appears
  only when a window has at least two tabs, so a single-tab window looks and
  behaves exactly like 0.2.0. Clicking a tab selects it; the selected tab's
  grid refits and receives terminal focus.
- **Tab lifecycle.** An ordinary shell exit closes its tab, and its window when
  that was the last tab. Closing a window closes all of its tabs with one
  confirmation. The last window closing quits OMXTerm. A spawn failure or
  unexpected signal stays visible in its native dialog until acknowledged, and
  only then is the useless tab removed. Nothing is preserved or reconnectable:
  tmux remains the session manager.
- **Tab keybinds.** The `keybinds` vocabulary gains `newTab`, `closeTab`,
  `nextTab`, `previousTab`, and `selectTab1` through `selectTab9`, defaulting to
  `Cmd+T`, `Cmd+W`, `Ctrl+Tab`, `Ctrl+Shift+Tab`, and `Cmd+1` through `Cmd+9`
  (literal positions). All remain remappable and duplicate-checked on the
  effective map.
- **Per-session titles and bell.** Terminal Titles stay display-only and are now
  per session: a tab shows its own sanitized OSC 0/2 title and falls back to the
  Default Shell's name, while the native window title mirrors the selected tab
  with `OMXTerm` as the final fallback. BEL stays silent and prepends a marker
  to the ringing session's title — visible on its tab and, while that tab is
  selected, in the window title — and an unfocused window requests Dock
  attention once until the user focuses or interacts with it.
- **Close confirmation only for Busy Sessions.** `confirmClose` still guards
  closing a tab, closing a window, and quitting with one confirmation per
  action, but a close action now asks only when an affected session is Busy:
  its PTY foreground process is not the idle Default Shell. Closing idle
  sessions proceeds without a dialog.

## Incompatible changes

0.3.0 intentionally revises two published 0.2.0 contract points.

- **`Cmd+W` closes a tab, not a window.** Following the macOS convention,
  `closeTab` takes `Cmd+W` and `closeWindow` moves to `Cmd+Shift+W`. Users who
  remapped `closeWindow` in `config.json` keep their accelerator; users on the
  defaults must learn the new pair. No file migration is required.
- **Close confirmations no longer ask for idle sessions.** 0.2.0 asked on every
  guarded close and explicitly did not inspect child processes. OMXTerm now
  reads only the PTY's foreground process name, in memory, to decide whether a
  session is Busy; the name is never logged, displayed, or transmitted, and an
  unreadable name counts as Busy so the dialog still appears. Setting
  `confirmClose` to `false` disables every close confirmation as before.

## Supported Platform

The only Supported Platform is Apple Silicon (`arm64`) on Otávio's current
macOS environment. Intel Macs and other operating systems are not supported by
this version.

## Known limitations

- Tabs are ephemeral. They are not saved, restored, reordered, or moved between
  windows, and there are no splits, workspaces, or profiles. Those capabilities
  are deferred rather than permanently rejected; each returns only through its
  own issue and ADR.
- OMXTerm still has no saved or reconnectable sessions, Shell Integration,
  automatic updates, AI assistance, or built-in remote terminal features.
  Closing a tab ends its Live Terminal Session; tmux remains the session
  manager.
- User Configuration and external Terminal Theme changes require a restart.
  Snippets remain the exception: `snippets.json` is reread each time the
  Snippets Sidebar opens.
- Window Font Zoom applies to every tab in its window and is still not
  persisted. The Snippets Sidebar belongs to the window and injects into the
  selected tab's session.
- The Busy Session check is deliberately name-only: it compares the PTY's
  foreground process name against the Default Shell's name. A nested idle shell
  therefore counts as idle.
- Distribution is Apple Silicon-only and intentionally unsigned and not
  notarized.

## Compatibility and migration

Version 1 `config.json`, `snippets.json`, and Terminal Theme files from 0.2.0
are accepted unchanged; the new tab actions are optional additions to the same
version 1 `keybinds` schema. No file migration is required. The only behavioral
differences for existing files are the two incompatible changes described
above, both of which concern shortcuts and confirmations rather than file
contents.
