# OMXTerm 0.4.0

[Historical release record](README.md): behavior and evidence below apply to
this version, not current product guidance or release requirements.

> Published 2026-07-24: the accepted macOS, Linux, and Windows ARM64 artifacts
> are attached to the [v0.4.0 GitHub Release](https://github.com/luizomf/omxterm/releases/tag/v0.4.0).

OMXTerm 0.4.0 is the first release for all three initial Supported Platforms:
macOS arm64, Linux arm64, and Windows arm64.

## What is new

- **Linux and Windows packages.** OMXTerm now ships a Linux ARM64 AppImage and a
  Windows ARM64 NSIS installer alongside the Apple Silicon DMG. Linux defaults
  to Electron's X11 backend and uses XWayland in a Wayland session. Windows
  starts Windows PowerShell as a plain interactive Default Shell, falling back
  to the `ComSpec` command processor.
- **Native file and folder insertion.** Dropping files or folders from the
  platform file manager into a Terminal Window inserts their absolute paths in
  the selected tab through Protected Paste without sending Enter. When the
  clipboard contains no non-empty plain text, Paste can insert a supported
  native file list in the same form. Paths are independently quoted for the
  platform's Default Shell.
- **Cross-platform application shortcuts.** Linux and Windows use shifted
  terminal shortcuts such as `Ctrl+Shift+C`, `Ctrl+Shift+V`, and
  `Ctrl+Shift+T`, preserving terminal control-letter combinations such as
  `Ctrl+C` and `Ctrl+V` as PTY input. A valid custom keybind that shadows a
  common PTY control key remains active but now produces a visible warning.

## User-visible fixes

- The `Ctrl+Tab` and `Ctrl+Shift+Tab` tab-cycling shortcuts that were broken in
  0.3.0 now work. The same delivery path supports any accepted keybind that the
  platform menu does not fire.
- Closing a requested tab now completes its PTY cleanup, so closing the last tab
  also closes its window as intended.
- Emoji-presentation sequences, keycaps, and ZWJ emoji clusters render as
  single two-column cells instead of overlapping neighboring cells.
- The empty xterm scrollbar gutter no longer appears on platforms with classic
  scrollbars; the real scrollback thumb remains available when needed.
- The Snippets Sidebar now follows the active Terminal Theme, including light
  themes.

## Known limitations

- On Linux ARM64, BEL remains silent and marks the ringing session's title, but
  an unfocused Terminal Window does not request native platform attention
  ([#135](https://github.com/luizomf/omxterm/issues/135)).
- The Linux About panel shows incomplete product metadata and a missing icon;
  the Terminal Window and documented desktop integration still use the correct
  OMXTerm icon ([#134](https://github.com/luizomf/omxterm/issues/134)).
- Linux native Wayland rendering is not currently claimed; a Wayland session
  must provide XWayland. Normal AppImage mounting requires FUSE 2, with
  `--appimage-extract-and-run` available as the fallback. A directly run
  AppImage needs the documented desktop-entry integration for its correct icon
  to appear in GNOME's dock and app grid.
- On Windows, ConPTY does not expose the foreground process name, so every live
  session counts as Busy. With `confirmClose` enabled, closing a live tab,
  window, or the application asks once. Electron 43 clipboard Paste can read
  only one Explorer file path; dropping multiple files remains complete and
  ordered.
- Tabs and Live Terminal Sessions remain ephemeral. OMXTerm has no splits,
  saved or reconnectable sessions, Shell Integration, automatic updates, AI
  assistance, or built-in remote terminal features; tmux remains the session
  manager.

## Compatibility and migration

There are no incompatible changes and no manual migration. Version 1
`config.json`, `snippets.json`, and Terminal Theme files accepted by 0.3.0 are
accepted unchanged. The new platform defaults apply only on Linux and Windows.

## Unverified packages and provenance

All three packages intentionally carry no verified publisher identity. The
macOS DMG is also not notarized. Its assembled application has an incomplete
ad-hoc code seal: after a browser download, macOS may report that the app is
damaged instead of offering the ordinary per-application Gatekeeper review.
This is a 0.4.0 packaging defect, not a missing Electron installation. Do not
disable Gatekeeper or install Electron separately; the seal was corrected in
[0.4.1](0.4.1.md). Use the [current downloads](../../README.md#platforms-and-downloads)
for installation.

The Linux AppImage provides no verified publisher identity. Microsoft Defender
SmartScreen may identify the Windows installer as coming from an unknown
publisher; `More info -> Run anyway` applies only to that file. Review the
source, verify the matching SHA-256, and proceed only if you trust the exact
artifact. Do not disable system-wide macOS security protections,
SmartScreen, or other system-wide Windows security protections.

These provenance statements do not mean OMXTerm was independently audited,
approved by Apple or Microsoft, or guaranteed free of defects in all code and
dependencies.
