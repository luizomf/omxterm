# OMXTerm 0.4.1

OMXTerm 0.4.1 is a packaging-only patch for macOS installation. Terminal
behavior is unchanged from 0.4.0.

## Fixed

- **Valid macOS application bundle integrity.** The Apple Silicon application
  now receives a complete ad-hoc code seal. The 0.4.0 packager skipped this
  pass, leaving an incomplete linker-generated signature that made Gatekeeper
  report a browser-downloaded clean installation as damaged. Electron and all
  native runtime components remain bundled; users do not install Electron or
  another runtime separately.
- **Release regression coverage.** Native package verification now requires
  `codesign --verify --deep --strict`, rejects unexpected publisher identities,
  and covers the exact incomplete-seal failure shipped in 0.4.0. The release
  checklist now requires a browser-quarantined clean-machine macOS install.

## Validation provenance

The initial three-platform 0.4.0 release received exhaustive native human
testing on macOS, Linux, and Windows. OMXTerm for macOS is continuously
dogfooded by maintainer Otávio Miranda as his personal terminal. Starting with
0.4.1, releases use native automation first and add targeted human checks only
for changed boundaries that automation cannot reliably observe. The macOS
code-seal fix received a browser-quarantined clean-machine Gatekeeper check;
Linux and Windows community testing remains welcome.

This process history is not an independent security audit, platform-vendor
approval, or guarantee.

## Known limitations

- On Linux ARM64, BEL remains silent and marks the ringing session's title, but
  an unfocused Terminal Window does not request native platform attention
  ([#135](https://github.com/luizomf/omxterm/issues/135)).
- The Linux About panel shows incomplete product metadata and a missing icon;
  the Terminal Window and documented desktop integration still use the correct
  OMXTerm icon ([#134](https://github.com/luizomf/omxterm/issues/134)).
- Linux native Wayland rendering is not currently claimed; a Wayland session
  must provide XWayland. Normal AppImage mounting requires FUSE 2, with
  `--appimage-extract-and-run` available as the fallback. A directly run
  AppImage needs the documented desktop-entry integration for its correct icon
  to appear in GNOME's dock and app grid.
- On Windows, ConPTY does not expose the foreground process name, so every live
  session counts as Busy. With `confirmClose` enabled, closing a live tab,
  window, or the application asks once. Electron 43 clipboard Paste can read
  only one Explorer file path; dropping multiple files remains complete and
  ordered.
- Tabs and Live Terminal Sessions remain ephemeral. OMXTerm has no splits,
  saved or reconnectable sessions, Shell Integration, automatic updates, AI
  assistance, or built-in remote terminal features; tmux remains the session
  manager.

## Compatibility and migration

There are no incompatible changes, configuration changes, or manual migration.
Version 1 `config.json`, `snippets.json`, and Terminal Theme files accepted by
0.4.0 are accepted unchanged.

## Publisher identity and provenance

All three packages intentionally carry no verified publisher identity. The
macOS application has a complete ad-hoc integrity seal, which provides bundle
integrity without identifying a publisher or replacing notarization. The Linux
AppImage likewise provides no verified publisher identity.

> OMXTerm for Apple Silicon is intentionally not signed with an Apple Developer
> ID and is not notarized. macOS may warn that it cannot verify the developer or
> check the app for malicious software. Review the source, verify the published
> SHA-256, and proceed only if you trust this exact artifact. If you choose to
> open it, follow Apple's current [Open Anyway instructions](https://support.apple.com/102445)
> in System Settings -> Privacy & Security. Do not disable system-wide macOS
> security protections. This is the open-source build Otávio published and
> uses; it is not independently audited, approved by Apple, or guaranteed free
> of defects in all code and dependencies.

> OMXTerm for Windows ARM64 is intentionally not signed with a code-signing
> certificate. Microsoft Defender SmartScreen may warn that the installer is
> from an unknown publisher. Review the source, verify the published SHA-256,
> and proceed only if you trust this exact artifact. If you choose to install
> it, use SmartScreen's `More info -> Run anyway` for this one file. Do not
> disable SmartScreen or other system-wide Windows security protections. This
> is the open-source build Otávio published and uses; it is not independently
> audited, approved by Microsoft, or guaranteed free of defects in all code and
> dependencies.
