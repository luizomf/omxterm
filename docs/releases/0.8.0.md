# OMXTerm 0.8.0

> Published as the [v0.8.0 GitHub Release](https://github.com/luizomf/omxterm/releases/tag/v0.8.0).
> The exact native artifacts were built and verified from source commit
> `b26df9ad1b629a7ed73bc6f3a9d77334a78a6334`, then optionally tested and
> accepted by Otávio on every Supported Platform.

OMXTerm 0.8.0 adds runtime configuration reload, explicit launch requests,
draggable tab ordering, and an optional Linux desktop installer. It also
improves sustained terminal-output handling and native package verification.

## What is new

- **Smoother bounded terminal output.** Payloads that are already safely within
  the IPC byte bound avoid unnecessary character-by-character splitting, while
  oversized Unicode payloads remain losslessly chunked. The Terminal Surface
  coalesces output received during one animation frame into one ordered xterm
  write, preventing a callback backlog during sustained output without turning
  Terminal Payload into application history.
- **Manual User Configuration and Terminal Theme reload.** `View -> Reload User
Configuration` (`Cmd+Shift+,` on macOS and `Ctrl+Shift+,` on Linux and
  Windows by default) rereads and validates the complete `config.json`, including
  its selected external Terminal Theme. A valid document applies atomically to
  current and future windows, tabs, and Terminal Surfaces without restarting
  their Live Terminal Sessions. A failed reload keeps the complete last valid
  in-memory configuration and reports the current actionable error. Reload is
  explicit; there is no file watching or automatic reload.
- **Explicit startup commands.** `-e <program> [arguments...]` runs the
  executable and literal argument vector directly in the first Terminal Tab of
  a new OMXTerm process. OMXTerm does not construct a shell command or rewrite
  arguments. Later tabs and windows use the Default Shell, and a trailing `-e`
  is an actionable startup failure rather than a silent fallback.
- **Draggable tab ordering.** Dragging a Terminal Tab horizontally reorders tabs
  within its current Terminal Window. Cycling and positional selection follow
  the new order while the selected tab, Live Terminal Sessions, and Terminal
  Surfaces remain unchanged. Ordering is ephemeral and tabs still cannot move
  between windows.
- **Optional transactional Linux desktop installation.** The release adds
  `OMXTerm-0.8.0-arm64.AppImage-installer.sh` alongside the Linux AppImage. The
  helper accepts only a user-supplied local Linux ARM64 OMXTerm AppImage, makes
  no network request, and transactionally owns the per-user AppImage, icon, and
  desktop entry. It chooses direct kernel-FUSE launch or
  `--appimage-extract-and-run` at installation time, rolls back failed updates,
  and removes only its fixed ownership set on uninstall. Its installed desktop
  entry now uses the installed hicolor icon correctly. Running the AppImage
  directly and manual desktop setup remain supported.
- **Less intrusive native menus.** Linux and Windows Terminal Windows now
  auto-hide the native application menu. Pressing and releasing Alt reveals it
  temporarily; using or dismissing it hides it again. macOS menu behavior is
  unchanged.

## Platform and packaging changes

- Linux continues to default to Electron's X11 backend. Wayland sessions require
  XWayland; an explicit Electron `--ozone-platform` choice still overrides the
  default for diagnosis. Launch-request parsing keeps OMXTerm's Linux X11
  relaunch switch separate from literal `-e` arguments.
- The Linux AppImage uses electron-builder's static runtime and no longer
  depends on the development-only unversioned `libz.so` linker name or a system
  `libfuse2` library. Normal execution still requires kernel FUSE support; the
  extraction fallback remains supported.
- Linux packaging now emits the exact versioned AppImage helper and checksum
  records for both Linux assets. Native verification checks dependency and
  architecture metadata, exact filenames and versions, helper transactions,
  installed startup through extraction, and direct FUSE startup when that seam
  is available.
- Packaged startup verification exercises explicit-command argv and session
  readiness. The Windows verifier also binds each packaged-process argument to
  its intended launch instead of sharing mutable argument state.
- Type-aware linting with zero accepted warnings is now part of the portable
  quality gate used before native package verification.

## Native artifact verification

All three native commands passed from source commit
`b26df9ad1b629a7ed73bc6f3a9d77334a78a6334`: `npm run check` on Apple Silicon
macOS, `npm run check:linux` on Linux ARM64, and `npm run check:win` on Windows
ARM64. Each command covered the applicable portable suite, native architecture,
package contents and licenses, embedded 0.8.0 version, package extraction or
installation seam, startup, PTY readiness, required Operational Events, and
verifier cleanup. macOS additionally passed the complete strict ad-hoc seal
verification; Linux verified both asset checksums and the transactional desktop
installer; Windows verified complete NSIS extraction and ConPTY startup.

Otávio accepted these exact artifact identities after optional testing on
macOS, Linux, and Windows, including two Apple Silicon Macs. The published
artifacts are immutable; rebuilding, changing, or replacing one would require a
new version and new exact-artifact verification and acceptance.

## Changed-boundary verification plan

This map identifies the automated seam and remaining automation-resistant risk
for every material boundary changed since `v0.4.1`. The exact 0.8.0 native
commands passed the applicable seams above; `UNVERIFIED` entries remain honest
risk rather than inferred passes.

- Bounded IPC fast path and frame-coalesced output -> terminal-contract and
  Terminal Surface unit tests cover byte bounds, Unicode preservation, exact
  ordering, sustained frames, and disposal. `UNVERIFIED`: perceived native
  rendering smoothness under platform-specific high-volume workloads.
- Complete manual configuration and Terminal Theme reload -> configuration,
  reloader, active-state, preload/IPC, Terminal Window, renderer host, Terminal
  Tabs, and Terminal Surface tests cover atomic success, whole-state rejection,
  warnings, runtime geometry, zoom, scrollback, Option Key Mode, theme, and PTY
  refit. `UNVERIFIED`: exact-artifact native font/theme rendering after reload
  on macOS, Linux, and Windows.
- Explicit `-e` Launch Request -> launch parser, application/session lifecycle,
  IPC, failure, Linux backend, and packaged-verifier tests cover literal argv,
  one-time consumption, failures, cleanup, and packaged startup.
- In-window tab dragging -> renderer Terminal Tabs and window-host tests cover
  reorder state, selection/session identity, positional navigation, window
  isolation, and native-file-drop separation. `UNVERIFIED`: exact-artifact
  pointer feel and visual tab presentation on macOS, Linux, and Windows.
- Linux X11 default and relaunch interaction -> Linux display-backend tests and
  native packaged startup cover switch selection, user overrides, startup, and
  PTY readiness. `UNVERIFIED`: visible X11/XWayland rendering and window-system
  presentation on the exact Linux artifact.
- Linux static AppImage runtime -> packaged dependency inspection rejects
  unversioned `libz.so`; Linux native package verification covers architecture,
  contents, extraction startup, and direct FUSE startup when available.
- Optional Linux installer, transactional updates, checksums, and installed icon
  -> installer/helper unit tests plus native package verification cover input
  validation, rollback, fixed ownership, checksums, desktop-entry/icon contents,
  uninstall, and installed startup. `UNVERIFIED`: GNOME or another desktop
  shell's displayed icon, app-grid association, and Dock integration for the
  exact artifact.
- Linux/Windows native menu auto-hide -> Terminal Window tests cover the native
  option by platform. `UNVERIFIED`: Alt reveal/dismiss interaction and native
  menu presentation on exact Linux and Windows artifacts.
- Package/verifier and final-version metadata -> release-version, Linux asset,
  and packaged-verifier tests plus each native `check` command cover source and
  embedded versions, exact names, architecture, package contents, licenses,
  startup, PTY readiness, checksums where applicable, and verifier cleanup.
  Gatekeeper and SmartScreen presentation remain automation-resistant platform
  behavior and are not inferred from package inspection.

The exhaustive 0.4.0 native exercise and ordinary macOS dogfood are historical,
non-blocking context only. For this release, Otávio additionally performed
optional exact-artifact testing on macOS, Linux, and Windows before acceptance.
Those observations are not automation, a reusable release gate, or a promise of
manual coverage for later releases.

## Supported Platform

The Supported Platforms remain Apple Silicon macOS, Linux ARM64, and Windows
ARM64. x64, Intel macOS, and other operating-system/architecture pairs are not
supported by this release. Every package intentionally carries no verified
publisher identity. The macOS application is required to have a complete ad-hoc
integrity seal, but it has no Apple Developer ID signature and is not notarized.

## Compatibility and migration

There are no incompatible schema changes and no manual file migration. Version
1 `config.json`, `snippets.json`, and Terminal Theme files accepted by 0.4.1 are
accepted unchanged. Existing configuration and themes can now be applied with
`View -> Reload User Configuration` instead of restarting OMXTerm. The new
`reloadConfig` keybind action is optional and keeps its platform default when
omitted.

## Known limitations

- On Linux ARM64, BEL remains silent and marks the ringing session's title, but
  an unfocused Terminal Window does not request native platform attention
  ([#135](https://github.com/luizomf/omxterm/issues/135)).
- The Linux About panel still shows incomplete product metadata and a missing
  icon ([#134](https://github.com/luizomf/omxterm/issues/134)). The Terminal
  Window and installed desktop entry use the OMXTerm icon.
- Linux native Wayland rendering is not claimed; a Wayland session must provide
  XWayland. Normal AppImage execution requires kernel FUSE support, with
  `--appimage-extract-and-run` available as the fallback.
- On Windows, ConPTY does not expose the foreground process name, so every live
  session counts as Busy. With `confirmClose` enabled, closing a live tab,
  window, or the application asks once. Electron 43 clipboard Paste can read
  only one Explorer file path; dropping multiple files remains complete and
  ordered.
- Tabs and Live Terminal Sessions remain ephemeral. Tab order is not saved, and
  tabs cannot move between windows. OMXTerm has no splits, saved or
  reconnectable sessions, Shell Integration, automatic updates, AI assistance,
  or built-in remote terminal features; tmux remains the session manager.

Linux AppImage is unsigned. The macOS application uses only its required ad-hoc
integrity seal.
